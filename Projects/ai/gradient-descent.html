~/overview

[ read ]

Gradient descent updates model parameters to reduce a loss. Writing the update yourself makes it easier to see how the learning rate, the choice of training examples, and regularization affect the path to a solution. This collection explores those choices using small linear-regression experiments.

~/how-it-works

[ walkthrough ]

features → prediction → loss → gradient → parameter update → repeat

  1. Define a prediction function and a loss whose derivative can be computed consistently.
  2. Calculate the gradient with respect to the weights, not merely the absolute prediction error.
  3. Choose which examples contribute to each update: the full dataset or a smaller batch.
  4. Stop after a fixed budget or a meaningful convergence check, then inspect predictions on data outside the training set.

~/key-code-idea

[ python ]

Illustrative sketch. This is a shortened teaching example or pseudocode, not a complete runnable notebook or a verbatim source excerpt.

# Mean squared error for a linear model without a bias term.
residual = X @ weights - targets
gradient = 2 * X.T @ residual / len(X)
weights = weights - learning_rate * gradient

The residual retains its sign, so the gradient tells us which direction changes the loss. Subtracting the gradient moves downhill locally. The factor 2 and normalization by the number of rows follow from the stated mean-squared-error objective; a different loss needs a different derivative.

~/implementation-notes

[ inspect ]
  • The simple, momentum, and weight-decay notebooks use absolute errors inside their gradient calculation. That is not the standard derivative of mean squared error.
  • The purpose of these examples is learning. The corrected sketches on the individual pages are labeled so they are not mistaken for exact notebook excerpts.
  • Compare variants with the same data and objective. Otherwise differences in the final error may have little to do with the optimizer.
