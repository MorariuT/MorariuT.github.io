Stochastic Gradient Descent_

A closer look at the problem, the data flow, and the code.

~/overview

[ read ]

A full-dataset gradient can be expensive. Stochastic gradient descent uses one example at a time; mini-batch gradient descent uses a small group. The notebook’s batch_size parameter places it in the mini-batch family.

Things From ScratchPython / notebooks

~/how-it-works

[ walkthrough ]

shuffle rows → disjoint mini-batches → gradient per batch → repeated updates

  1. Shuffle feature rows and targets with the same permutation at the start of an epoch.
  2. Slice a batch of aligned examples.
  3. Calculate a gradient from that batch and update the weights immediately.
  4. Continue until every row has been visited. Repeat for multiple epochs.

~/key-code-idea

[ python ]

Illustrative sketch. This is a shortened teaching example or pseudocode, not a complete runnable notebook or a verbatim source excerpt.

# Corrected non-overlapping mini-batch traversal.
order = rng.permutation(len(features))
for start in range(0, len(order), batch_size):
    rows = order[start:start + batch_size]
    gradient = mse_gradient(features[rows], targets[rows], weights)
    weights -= learning_rate * gradient

An epoch is one pass through all training rows. Stepping by batch_size creates distinct slices, and using len(order) as the upper bound covers the complete dataset. The final batch can be smaller; a mean-gradient implementation should divide by its actual size.

~/implementation-notes

[ inspect ]
  • The notebook loops from 0 to batch_size with a step of one, creating overlapping batches rather than traversing the whole shuffled dataset.
  • Its gradient uses y minus prediction and its update adds that value. Those signs can be consistent together; compare the complete formula rather than one line in isolation.
  • Noisy training loss is expected when updates use small subsets. Evaluate at a consistent point, such as the end of each epoch.
