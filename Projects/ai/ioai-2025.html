~/how-it-works

[ walkthrough ]

task statement → dataset inspection → validation split → baseline → experiments → submission

  1. Use the portal’s task statement as the specification. Different rounds can have different modalities, target formats, and evaluation rules; choose the matching notebook before reading any model code.
  2. Create a local validation set that resembles the challenge’s test conditions. Fit preprocessing and train the model using only the training portion.
  3. Record a simple baseline before changing the model. Compare experiments using the same split and the same metric.
  4. Inspect the submission writer last. Every prediction must remain aligned with the correct identifier and required column.

The validation result is useful only when the split and metric match the problem. A model that looks strong on a random split can fail when the hidden test set represents later dates, unseen groups, or different data sources. A submission file also needs correct row identity, not merely the expected number of predictions.
