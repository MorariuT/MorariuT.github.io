Momentum Gradient Descent_

A closer look at the problem, the data flow, and the code.

~/overview

[ read ]

Momentum gives gradient descent a memory. Instead of choosing each step from the newest gradient alone, it maintains a velocity vector. Consistent gradients accumulate movement, while alternating gradients can partially cancel.

Things From ScratchPython / notebooks

~/how-it-works

[ walkthrough ]

gradient + previous velocity → new velocity → parameter update → persist velocity

  1. Create a velocity array with the same shape as the weights before training begins.
  2. Compute a gradient from the current training data.
  3. Combine a fraction of the previous velocity with the new downhill step.
  4. Add the velocity to the weights and keep it for the next iteration.

~/key-code-idea

[ python ]

Illustrative sketch. This is a shortened teaching example or pseudocode, not a complete runnable notebook or a verbatim source excerpt.

# Corrected vector momentum update.
velocity = np.zeros_like(weights)
for step in range(max_steps):
    gradient = mse_gradient(features, targets, weights)
    velocity = momentum * velocity - learning_rate * gradient
    weights += velocity

Each parameter needs its own persistent velocity. The momentum coefficient determines how much history survives. A value near one retains a longer memory; a value of zero reduces the method to an ordinary gradient step.

~/implementation-notes

[ inspect ]
  • In the notebook, v is a scalar initialized inside update_weights. It is reused while iterating over coordinates and is reset at the next call. That differs from persistent per-parameter momentum.
  • Momentum does not fix an incorrect gradient. Check the derivative separately before comparing convergence speed.
  • Use the same initialization and learning objective when comparing this variant with ordinary gradient descent.
